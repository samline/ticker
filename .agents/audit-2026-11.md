# Audit 2026-11 (3.0.0): lessons and open items

## Lessons

- `overflow: hidden` is still programmatically scrollable. Focus reveal, find-in-page and fragment
  navigation scroll the wrapper and silently offset the transform loop. The runtime now converts
  wrapper scroll into a logical seek; keep that in mind before switching to `overflow: clip`
  (which would make offscreen originals unrevealable instead).
- Cloning copies `id` attributes, so registry sources (and any id in content) are duplicated in
  clones. Stripping ids from clones was tried and reverted: id-based styles (`#news > *`, the runtime
  e2e fixtures) stopped applying to clones and broke loop geometry. Keep authored ids; document.
- A drag-suppressed click flag must be cleared after release: touch drags emit no click, so a
  sticky flag swallowed the next keyboard activation.
- Registry state must follow controller destruction from every owner (direct `destroy()`, manager
  DOM removal), via the `destroy` event.
- IntersectionObserver may deliver several entries per target per callback; use the last.
- Verify fixes against the old code: every regression test in `tests/regressions.test.ts` and the
  focus-scroll / touch-activation cases in `landing/e2e/runtime.spec.ts` fail on 2.6.0 source.
- Axe's experimental `label-content-name-mismatch` flags the brand link, docs search trigger and
  aria-pressed toggles; their names begin with the visible label, so they were left unchanged.

## Resolved follow-ups (folded into 3.0.0 before publication)

- Clones drop `name` from form controls (before insertion, so a checked clone radio cannot steal
  the group's checked state). Ids stay, see above.
- Destroying an adopted wrapper removes runtime `--ticker-*` properties, the track hover-pause class
  and option classes it did not carry before adoption.
- Removed the duplicate `cancelNavigation()` in `update()`.
- The vertical inertia e2e assertion only requires real motion: the short 9px vertical moves make
  release velocity runner-dependent, which caused a one-off failure under full-suite load.

## Ported from the package-landing-docs template audit

- `button.icon-button` and `.search .search-trigger` state their precedence over the ghost Button
  padding instead of relying on stylesheet order (Ticker rendered correctly; the template squeezed
  icons once CSS was inlined). Docs browser test checks square header icons at 375px.
- Malformed percent-encoding (`#100%`) no longer throws: the ToC keeps the literal id and the link
  audit reports "Malformed percent-encoding" (Node tests added).
- Not applicable here: the Hero already keeps whitespace around its desktop break, the footer has no
  external-marked Changelog link and Ticker's Playwright ports (4324/4327) are not shared.
