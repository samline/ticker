Ticker uses the same browser API in each host; there is no framework adapter or peer dependency to install. **Package / ESM** imports `ticker()` and its stylesheet. **HTML / CDN** calls `window.Ticker.ticker()` after loading the standalone script and stylesheet. Keep delivery separate from ownership; see [loading terms](../html-and-browser/#loading-terms).

## JavaScript and TypeScript

Start with [installation](../../getting-started/). JavaScript uses the same calls without type annotations. TypeScript can import `TickerOptions` and `TickerInstance` from the root; use `satisfies TickerOptions` to check reusable settings. The [TypeScript reference](../../reference/typescript/) lists every exported type.

## React, Vue and Svelte

Install Ticker in an existing framework project, save the component and its CSS sibling, then render `NewsTicker`. These examples include a Pause/Play action that follows requested playback, including reduced-motion or other automatic pauses. They create after client mount and destroy before the component leaves. React's example also supports its development setup/cleanup cycle.

<FrameworkExamples label={t.label} groups={frameworkFiles} />

The enhanced source DOM belongs to Ticker until `destroy()` restores it. Keep this subtree stable while mounted: use a component ref for the controller, `update()` for settings, and `refresh()` after application-owned source edits. Do not replace the runtime's track/clones from a framework render. For reactive item lists, tear down before the framework replaces the original nodes, then initialize the new source. Do not place framework components in generated clones.

The lifecycle hooks follow [React Effects](https://react.dev/reference/react/useEffect), [Vue mount/unmount hooks](https://vuejs.org/api/composition-api-lifecycle.html) and [Svelte onMount cleanup](https://svelte.dev/docs/svelte/lifecycle-hooks).

## Astro

Import and call `ticker()` inside a processed client `<script>`, not frontmatter. The [first integration](../../getting-started/) is ordinary browser JavaScript and needs no hydrated framework component. With Astro client navigation, initialize the current page after `astro:page-load` and destroy the owning instances on `astro:before-swap`; keep document listeners registered once. Full-page examples preserve instances on persisted `pagehide` and clean up on a real departure.

### Deferred Astro content and interactive copies

Keep the browser setup in the host component so it is present before deferred
HTML arrives. This complete `TickerFeed.astro` wrapper accepts translated action
labels and a deferred source through its default slot. It waits for the source,
uses one gap for items and loop boundaries, and delegates selection from both
originals and interactive copies. It does not fetch a CMS or invent data.

```astro
---
interface Props {
  playLabel: string
  pauseLabel: string
}
const { playLabel, pauseLabel } = Astro.props
---

<ticker-feed data-play={playLabel} data-pause={pauseLabel}>
  <slot />
  <button type="button" data-feed-toggle disabled>
    {pauseLabel}
  </button>
  <output data-feed-status aria-live="polite"></output>
</ticker-feed>

<script>
  import { ticker } from '@samline/ticker'
  import '@samline/ticker/style.css'

  const owners = new Map<HTMLElement, () => void>()
  const setup = () => {
    document.querySelectorAll<HTMLElement>('ticker-feed').forEach(root => {
      if (owners.has(root)) return
      const toggle = root.querySelector<HTMLButtonElement>('[data-feed-toggle]')!
      const status = root.querySelector<HTMLOutputElement>('[data-feed-status]')!
      const listeners = new AbortController()
      let controller: ReturnType<typeof ticker> = null
      const observer = new MutationObserver(() => mount())
      const mount = () => {
        const source = root.querySelector<HTMLElement>('[data-feed-source]')
        if (!source || controller) return
        controller = ticker(source, { interactiveClones: true, pauseOnHover: false })
        if (!controller) return
        observer.disconnect()
        const render = () => {
          toggle.textContent = controller!.state.requested
            ? root.dataset.pause!
            : root.dataset.play!
        }
        controller.on('playback', render)
        render()
        toggle.disabled = false
      }
      owners.set(root, () => {
        observer.disconnect()
        listeners.abort()
        controller?.destroy()
        owners.delete(root)
      })
      toggle.addEventListener(
        'click',
        () => {
          if (controller?.state.requested) controller.pause()
          else controller?.play()
        },
        { signal: listeners.signal }
      )
      root.addEventListener(
        'click',
        event => {
          const target = event.target instanceof Element ? event.target : null
          const action = target?.closest<HTMLButtonElement>('[data-feed-select]')
          if (action && root.contains(action)) status.textContent = action.dataset.message ?? ''
        },
        { signal: listeners.signal }
      )
      observer.observe(root, { childList: true, subtree: true })
      mount()
    })
  }
  const cleanup = () => [...owners.values()].forEach(dispose => dispose())
  setup()
  document.addEventListener('astro:page-load', setup)
  document.addEventListener('astro:before-swap', cleanup)
  window.addEventListener('pagehide', event => {
    if (!event.persisted) cleanup()
  })
</script>

<style is:global>
  ticker-feed [data-feed-source],
  ticker-feed .ticker-track {
    gap: 1.5rem;
  }
  ticker-feed [data-feed-source] {
    display: flex;
    width: max-content;
  }
  ticker-feed [data-feed-select] {
    flex: none;
  }
</style>
```

The deferred `FeedItems.astro` supplies the ready source. The `items` prop here is
already translated public data; replace its source inside this component with
your validated provider loader if request-time data is needed:

```astro
---
interface Props {
  items: readonly { id: string; label: string; selectionMessage: string }[]
}
const { items } = Astro.props
---

<div data-feed-source>
  {items.map(item => (
    <button type="button" data-feed-select={item.id} data-message={item.selectionMessage}>
      {item.label}
    </button>
  ))}
</div>
```

The owning page/section composes
`<TickerFeed playLabel={copy.play} pauseLabel={copy.pause}><FeedItems server:defer items={items} /></TickerFeed>`
with those components imported, a configured adapter and actual translated copy.
Do not put `data-feed-source` on fallback markup: initialization must wait for
the real source. Keep setup in the host, rather than relying on scripts inserted
with deferred HTML. A production provider failure needs translated error UI.

Focus still pauses playback; the explicit button retains manual pause. Clones
share delegated actions, so do not bind listeners separately to original cards.
Do not put unique IDs, hydrated framework components or stateful forms in these
copies. This wrapper owns normal document/Astro navigation cleanup; applications
that independently replace its root must dispose that owner before replacement.

## Shopify

Use a theme section and theme assets. Copy the matching published release `dist/browser/global.global.js` as `assets/ticker.global.js` and `dist/style.css` as `assets/ticker.css`; save the JavaScript and CSS below beside them. Add the loader once in `layout/theme.liquid`, then add `sections/ticker-strip.liquid` in the theme editor. The section itself contains no extra runtime script tags.

<CmsExamples host="shopify" />

The loader creates independent instances for repeated sections, handles `shopify:section:load`, and destroys only the removed section on `shopify:section:unload`. Static content remains readable without JavaScript. [Shopify's section lifecycle](https://shopify.dev/docs/storefronts/themes/best-practices/editor/integrate-sections-and-blocks) and [asset loading](https://shopify.dev/docs/storefronts/themes/best-practices/javascript-and-stylesheet-tags) describe this host contract.

## WordPress

Create `wp-content/plugins/ticker-example/` with the plugin PHP file below and an `assets/` folder. Save the same pinned runtime files there as `ticker.global.js` and `ticker.css`, plus the provided `integration.js` and `integration.css`. Activate **Ticker example**, then put `[ticker_strip]` in a Shortcode block on a normal post or page.

<CmsExamples host="wordpress" />

This example targets WordPress 6.3+ deferred-script arguments. Runtime and integration scripts are queued with explicit dependencies, so markup is present before initialization. The sample loads assets for ordinary singular content containing the shortcode; widgets, page builders and AJAX navigation need their own enqueue/mount policy. Do not paste a second IIFE into each shortcode. See [wp_enqueue_script](https://developer.wordpress.org/reference/functions/wp_enqueue_script/) and [frontend asset hooks](https://developer.wordpress.org/reference/hooks/wp_enqueue_scripts/).

## Ownership and accessibility

Keep original content meaningful and provide a pause action for moving content. Ticker owns clones, measurements, reduced-motion handling and automatic pause causes. Each host owns its original DOM, labels, subscriptions and teardown. Closing a page widget is not permission to destroy unrelated registry entries; see [lifecycle ownership](../lifecycle/) and [accessibility](../accessibility/).
