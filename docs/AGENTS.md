# Documentation implementation and maintenance contract

Read README.md before changing the docs. This site replaces Starlight; `src/content/docs/` is the sole maintained prose source. Keep user edits. All contributor-facing documentation is in English.

- Use Astro 7, Tailwind 4, `class:list={[...]}` and rem for fixed authored CSS lengths. Components own scoped styles and processed scripts. Reusable controls belong in components; complete document structure belongs in layouts. Do not add a global component stylesheet or initialization script.
- Share the shared theme tokens and Box/Theme/ThemeToggle/CopyButton intentionally. Do not fork their palette, clipboard behavior or theme persistence. A shared-control change must be checked in both sites.
- Keep shell/interface text in `src/i18n/translations/<locale>/`, article prose and examples in Markdown frontmatter/body. Translate whole messages; never inject translated HTML. Structural identifiers and API syntax are not translations.
- Use content collections and the existing route helper. Keep all public routes/fragments, base paths, sitemap and canonical metadata synchronized. External and landing destinations must remain meaningful.
- Delegate Drawer animations, locking, focus, dismissal and teardown to the package. Native scoped vendor CSS is normalized to rem. Own only configuration, link dismissal, responsive close and cleanup. Test unchanged background scroll after closing.
- The sticky header measures its height. Content headings/main use scroll-margin, leaving 2.5rem beneath the header. Do not add global html scroll-padding; it breaks focus restoration. Never compensate with manual scrollTo.
- Every fenced code block gets the shared CopyButton. Copy exact code text and preserve two-second reset, failure selection, per-instance cleanup and the readable no-JavaScript fallback. Build-time code/table tabindex keeps overflow keyboard reachable.
- Search uses locally built Pagefind, loaded lazily. Index article content only, preserve heading URLs and `/ticker/docs/` paths, handle stale asynchronous results, error/empty states and cleanup. Keep keyboard and no-JavaScript navigation usable. Verify against a production build, not an unindexed dev server.
- Cover the entire package, including runtime functions, methods, browser registry, options, CSS/DOM, TypeScript/core exports, lifecycle/SSR, accessibility, migration and recipes. `migration-coverage.json` records all 33 former sources; do not treat a name audit as semantic proof. Review public claims against source, execute changed examples and correct obsolete references in the same change.
- `check-coverage.mjs` detects missing public export names, invalid named imports and stale CDN versions. Extend it for new public surfaces. Do not silence failures by mentioning names without documenting their actual contract.
- A package change requires reviewing root README, guides, API pages, types/configuration/styling/browser references, landing claims and runnable examples. A version change requires pinned CDN updates. A page/heading change requires content links, navigation, landing docsRoutes, redirects, pagination and search review.
- Run docs check, format check, build and relevant browser tests. Run root site:build, site:test:browser and landing checks for integration changes. Inspect 320–1440 and back, enlarged root text, both themes, reduced motion, keyboard, and no JavaScript. Do not conceal layout bugs with page overflow clipping. Automated axe evidence does not guarantee complete accessibility.
- Keep root scripts, CI/Pages workflows, artifact copying and sitemap merging aligned. Only maintained Markdown is shipped in npm; never publish site dependencies, generated pages or search assets. Verify npm pack after changing packaging.
- Update README.md and this file whenever conventions, contracts, commands or cross-project dependencies change. Replication must replace package-specific content, routes, imports, names, metadata and tests.
- For structural code exploration use the installed codebase-memory skill: graph first, coverage check, then exact source fallback for missing/stale/unsupported coverage. No graph result alone proves exhaustive coverage.

## Ticker 2.1 runtime contract

Playback intent, automatic pause causes, CSS-animation seeking, logical navigation, vertical measurements and viewport rules belong to the package runtime. Site demos call play()/pause(), state/on() and connectControls() rather than implementing pause CSS or gesture/rail controllers. Horizontal left/right stay physical; auto uses inherited writing direction, while next/previous and position are logical. Axis changes reset position; same-axis updates preserve pixels modulo the measured period. Keep pinned versions, public skill, copied recipes and the scoped package CSS adaptation synchronized. Runtime browser tests live in landing/e2e/runtime.spec.ts alongside the site suites.
